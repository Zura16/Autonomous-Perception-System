# Glossary

Terms **as used in this project**, plus canonical constants. Where a term is used
differently elsewhere in the literature, that is stated — an ambiguous term is
how two correct people reach incompatible numbers.

---

## Coordinate frames

Every bug in this stack is a frame bug or a units bug. These names appear in
code, verbatim.

| Frame | Axes | Notes |
|---|---|---|
| `velo` | x forward, y left, z up | Velodyne LiDAR. Full 360° sweep; only ~35% of forward returns land in the camera image |
| `cam0` | — | Unrectified left grayscale camera |
| `rect0` | x right, y **down**, z **forward** | Rectified reference frame. The optical axis is z |
| `cam2` | as `rect0` | Rectified left **colour** camera — the camera this project uses. Differs from `rect0` by `[+0.0598, −0.0004, +0.0027] m` |

**The chain:** `X_rect0 = R_rect_00 · Tr_velo_to_cam · X_velo`, then
`[u v w]ᵀ = P_rect_02 · [X_rect0; 1]`, with `u_px = u/w`, `v_px = v/w`.
The homogeneous divisor `w` **is** the depth in the cam2 frame.

**Sign trap:** KITTI's `P_rect_02[0,3]` is **positive** (+44.86 px). cam2 is
mounted ~6 cm to the left of cam0, so world points shift *right* in its image.
Getting this backwards is invisible in an overlay and asserted in
`test_camera_offset_shifts_pixels_but_not_depth`.

## Range and distance

Three different quantities that are all called "distance" in the wild. Mixing
them is a silent bias, not an error.

| Term | Meaning here |
|---|---|
| **`range_m`** | **The project's default.** Longitudinal distance (`z` in the cam2 frame) to the **nearest surface** of the object |
| `center_range_m` | Longitudinal distance to the 3D box centroid. **+2.03 m** farther than `range_m` on average (measured, dev split) |
| `euclidean_range_m` | Straight-line distance from the optical centre. Larger than `range_m` for off-axis objects |

Why near-face: a collision occurs when the *gap* reaches zero, and a 2D bounding
box is generated by the object's *visible face*, so both the physics and the
estimator agree on it. **Most published monocular-distance work reports centroid
distance** — any comparison to an external number must say which it uses.
See [D-003](decisions.md).

## Ground-truth vocabulary

| Term | Meaning |
|---|---|
| **The ruler** | The LiDAR-derived range ground truth in `aps/groundtruth.py`. Its own error (0.13 m MAE) is the floor under every range number |
| **GT tier** | `strict` (visible, untruncated) · `relaxed` (occlusion unlabelled) · `invalid` (occluded or truncated — **no ground truth exists**) |
| **Coverage** | Fraction of labelled objects that can be ground-truthed at all. Currently **64%** |
| **Abstention** | The estimator returning NaN rather than a low-confidence value. Counted, never filled in |
| **Amodal box** | A label covering an object's full extent including hidden parts. KITTI 3D boxes are amodal; LiDAR returns are not — which is why truncated boxes are `invalid` |

| Annotator flag | Values |
|---|---|
| `occlusion` | −1 unset · 0 visible · 1 partly · 2 fully |
| `truncation` | 0 in image · 1 truncated · 2 out of image · 99 behind image |

## Estimation and decision

| Term | Meaning |
|---|---|
| **Scale rate** | `ḣ/h`, the fractional rate of change of apparent box height. Closing speed follows as `Ḋ = −D·ḣ/h` |
| **Closing speed** | Rate of change of `range_m`, **negative when approaching**. Never obtained by differencing a depth estimate ([hard rule 3](../CLAUDE.md)) |
| **TTC** | Time to collision, `−D/Ḋ` under a constant-relative-velocity assumption — itself an approximation, and one that breaks under braking |
| **Deadband** | Threshold below which closing rate is forced to zero. Exists because a *parked* car must produce ≈0 closing speed, not phantom motion |
| **FCW** | Forward collision **warning**. An alert |
| **AEB request** | A signal that automatic braking is warranted. In this project it is a logged output. **Nothing is actuated** |
| **FP/hour** | False positives per hour of video. The number that matters for a warning system — a phantom brake at highway speed is itself the crash |

## Metrics

| Term | Meaning |
|---|---|
| **MAE / MAPE** | Mean absolute error (m) / mean absolute percentage error. Always reported **per range bin**, never pooled ([hard rule 2](../CLAUDE.md)) |
| **Bias** | Signed mean error. Distinguishes a miscalibration from noise; MAE alone hides it |
| **p95 \|e\|** | 95th percentile absolute error. The tail is what a safety argument turns on |
| **MOTA / IDF1 / ID-switches** | Tracking metrics. Here computed on KITTI *raw* tracklets, so **not comparable to the KITTI tracking leaderboard** ([D-004](decisions.md)) |
| **Operating envelope** | The range interval within which error stays below a stated threshold. The project's intended headline |
